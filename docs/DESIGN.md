# 余讯 6.1 · 设计说明

作品以「如果只有 1% Battery？」引导观众思考：资源有限时，如何用最少的内容涵盖最基本的信息。

## 体验结构

1. **1%**：占满视口的文字开场，直接提出问题；按钮始终可用，不等待动画完成。
2. **整理**：在 96 B 的初始预算内选择、编辑、分类消息，或按分类覆盖优先推荐。预算可调整。
3. **抵达**：读取实际编码后的完整文字和分类，形成独立于草稿的接收快照。
4. **留下**：沿用同一张便笺和阅读位置，显示本地留存结果，可下载完整文字。

主流程采用动态切页，章节按钮和键盘方向键均可操作；不依赖页面下滑。页面不包含全景系统、业务服务器交互或真实电池检测。

## 视觉与动效

纸白与深绿构成主要色彩，大数字和清楚的文字层级承担视觉表达。开场暂时收起导航和页脚，后续操作恢复导航。所有章节共用固定全屏舞台，避免切页时舞台尺寸突变。

开场数字只揭示一次；切页通过标题与内容的短位移动画和透明度变化衔接，不缩放整页文字。返回开场不重复首次揭示。用户启用减少动态效果时可立即切换，动画 API 失败也不阻断操作。

设计参考 Taste Skill 与 Impeccable 的相关指导：明确视觉焦点、保持对象连续性、使用克制且有目的的动效，不为动效增加不必要依赖。

## 信息规则

基本分类为「状态、位置、下一步、联系」，并提供「生活、稍后、未分类」。分类会随消息编码、计入实际字节并随便笺保留。

容量内推荐依次考虑：覆盖更多基本分类、保留更多完整消息、占用更少字节。推荐不截断原文，也不声称理解信息的重要程度；观众仍可修改和选择。分类覆盖不等于语义完整或安全保证。

## 实现取舍

采用原生 HTML、CSS、ES modules 和 Web Animations API，无运行时依赖。字体与 SVG 图标自托管，消息只在当前浏览器处理；本地启动器仅提供静态文件。

目前没有真实设备的节电、帧率和离线测试结果。自动化测试验证状态与数据规则，不把模拟结果描述为实测效果。
